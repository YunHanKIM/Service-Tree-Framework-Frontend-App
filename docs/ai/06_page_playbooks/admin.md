# 페이지 플레이북 — 관리자 (`src/app/(tabs)/admin.tsx`, `src/app/admin/*`)

관련 요청문: REQ-F-006, REQ-F-007, REQ-F-008, REQ-F-009

## 관리자 탭

- 상단: "물품 등록", "전체 기록".
- **승인 대기 신청** — 카드마다 "<이름> 신청 승인", 거절 사유 입력, "<이름> 신청 거절". 버튼 이름에 신청자를 넣어
  화면 읽기에서 어느 카드의 버튼인지 구분되게 했다.
- **반납 확인 대기** — "실물 확인, 반납 완료".
- **기한 경과** — 반납 예정일이 지난 활성 대여.

## 물품 등록·수정 (`admin/item-form.tsx`)

- `?id=`가 있으면 수정. 수정일 때만 사용 여부 스위치. 대여 중이면 서버가 `ITEM_ON_LOAN`으로 거부한다.
- 저장 후 상세 화면으로 `replace`.

## 전체 기록 (`admin/history.tsx`)

- 탭 두 개(신청 기록·대여 기록). 처리 시각·거절 사유·반납 시각을 보여준다.

## 알아야 할 것

- 역할 가드는 두 겹이다. 라우트(`Tabs.Protected`, `Stack.Protected guard={isAdmin}`)와 서버(데모 API `requireAdmin`, SQL RPC `is_admin()`).
- 승인 충돌(`CONFLICT`)은 다른 관리자가 같은 물품의 다른 신청을 먼저 승인했을 때 난다. 문구를 보여주고
  `AFFECTS.loan` 쿼리를 모두 다시 불러오므로 카드가 사라진다.
- 데모 백엔드는 브라우저 탭마다 따로라서, 두 기기 동시 승인은 데모 앱으로 재현되지 않는다. 동시성은
  `demoApi.test.ts`의 "두 관리자가 동시에 승인" 테스트로 검증한다.
